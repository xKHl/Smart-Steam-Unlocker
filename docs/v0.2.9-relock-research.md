# v0.2.9 Relock research notes

> **Historical design research — not a current-state specification.** This v0.2.9 record explains the rationale for per-achievement Relock. Validate any implementation change against current source, tests, [Architecture](ARCHITECTURE.md), and [Project Status](PROJECT_STATUS.md).

## Steamworks API

Valve's `ISteamUserStats::ClearAchievement(const char *pchName)` resets an achievement by its API name. Valve documents that this mutation is only in Steam's in-memory state until `ISteamUserStats::StoreStats()` sends it to the server. `ClearAchievement` returns `true` when the named, published achievement exists. Source: [ISteamUserStats API reference](https://partner.steamgames.com/doc/api/isteamuserstats).

Relevant documented lifecycle:

> `ClearAchievement` → `StoreStats` → observe separately propagated remote player state.

This supports Smart Steam Unlocker's local-first Relock design: request stats readiness, inspect current local unlocked state, call per-achievement clear, call StoreStats exactly once, and treat Web API confirmation as distinct remote evidence rather than proof of local execution.

## Steam Achievement Manager reference

Read-only clone: `/home/ubuntu/references/SteamAchievementManager`.

`SAM.API/Wrappers/SteamUserStats013.cs` routes `SetAchievement(name, false)` to native `ClearAchievement`; the same wrapper exposes `StoreStats()`. `SAM.Game/Manager.cs` applies individual achievement state changes and subsequently calls StoreStats. This validates per-achievement clear/persist mechanics but Smart Steam Unlocker retains its own Electron, stats-readiness, coordinator, and verification architecture.

Repository: <https://github.com/gibbed/SteamAchievementManager>

## Steam Game Idler reference

Read-only clone: `/home/ubuntu/references/steam-game-idler`.

`libs/SteamUtility/Cli/Commands/LockAchievementCommand.cs` invokes `SetAchievementAsync(appId, achievementId, unlock: false)`. The concrete `AchievementHandler.SetAchievementAsync` verifies a definition, protects unsupported/protected cases, clears the individual achievement bit, persists a changed stats record, and reports StoreStats/validation failures. It does not use a global reset for the single lock command.

Repository: <https://github.com/zevnda/steam-game-idler>

## Design conclusion

The v0.2.9 implementation uses Steamworks.js 0.3.2's installed `achievement.clear(achievementId): boolean` and `stats.store(): boolean` bindings. It will not use `stats.resetAll()` for the per-achievement Relock feature. It must preserve existing activation behavior, prevent coordinator conflicts, and communicate a pending state whenever local StoreStats succeeds but the remote Steam Web API has not yet shown the locked state.
